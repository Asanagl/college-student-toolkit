# v0.4.0 ACM 对拍功能架构记录

更新日期：`2026-08-30`

## 目标与已确认边界

- 新增独立的 ACM 对拍页面，不嵌入单文件 Workbench 页面。
- 页面提供标准程序、待测程序两个独立 C++ 编辑器，以及一份仅存在于当前页面会话的 stdin 输入框；首次打开均为空。
- 两份源码均支持打开文件、保存和另存为。未保存编辑内容不写入历史记录；关闭或刷新页面后丢弃。用户主动保存的文件仍由文件系统保留。
- 每次点击开始都重新编译两份源码，使用当前 ACM 编译器选择和相同 C++17 参数；标准程序编译/运行完成后才进入待测程序阶段，禁止复用旧可执行文件。
- 两个程序各自使用独立临时目录和现有主进程安全兜底：编译 30 秒、运行 3 秒、stdin 256 KiB、stdout/stderr 各 4 MiB、临时目录 128 MiB。限制不可由页面调整。
- 标准程序非零退出、超时、输出/临时目录超限或编译失败时，结果为“标准程序失败/对拍无效”，不运行待测程序，不产生 AC/WA。
- 待测程序失败使用独立状态（编译失败、运行超时、运行异常、输出/临时目录超限），不产生 AC/WA。
- 两侧正常退出（`exitCode = 0`）后，按所有空白字符切分 token 并逐 token 比较；token 内字符必须完全一致。
- AC 仅显示“输出一致”；WA 仅返回首个差异，前后各 3 个 token，并标记缺失或多余 token；不传输完整 stdout/stderr、退出码或耗时给 Renderer。
- 每个临时可执行文件在程序结束后立即删除；删除失败不阻断结果，返回清理警告并在主进程有限次数后台重试。
- ACM 插件禁用/不支持时页面可查看但不能执行；IPC handler 继续执行主进程插件门禁。
- Workbench 和对拍页共享一个持久化的提示关闭状态。关闭后两页均隐藏；插件禁用、应用版本变化或用户主动打开 ACM 设置时重新显示。

## 架构图与数据流

```text
ACM Diff Renderer (/acm-diff)
  ├─ 两个 CodeMirror 编辑器 + stdin（页面内存）
  ├─ 共享 PluginNotice 状态（持久化 dismiss marker）
  └─ window.api.acm.startDiff / onDiffEvent / open/save document
       ↓ preload 最小白名单
Main IPC handlers + zod
  ├─ AcmPluginService 门禁
  └─ AcmDifferService
       ├─ AcmCompilerService（同一编译器/flags）
       ├─ AcmRunnerHelper（Job Object / taskkill fallback）
       ├─ AcmRunnerService 限制/临时目录策略复用
       └─ token comparator（首个差异 + 3 token context）
```

对拍服务保持单一活动任务。一次任务内部依次执行：`reference-compile → reference-run → candidate-compile → candidate-run → compare → cleanup`。每个阶段发出带 `side` 的事件；完整 stdout 只在主进程内存中保留至比较完成，IPC 仅发送摘要和受限差异片段。

## 模块职责与接口契约

| 模块 | 职责 |
| --- | --- |
| `AcmDifferService` | 校验两份源码和 stdin，编排双编译/双运行，应用标准程序门禁，汇总结果，安排清理重试。 |
| `AcmTokenComparator` | UTF-8 文本按 `\\s+` token 化，返回 AC 或首个差异及双方前后 3 token。 |
| `src/shared/types.ts` | 对拍请求、事件、结果、提示 marker 和 IPC API 的唯一契约。 |
| `src/main/validation.ts` | 对拍请求、保存/打开参数和提示 marker 的 zod 边界校验。 |
| `src/main/main.ts` / `preload.ts` | 注册并暴露最小白名单；handler 先检查 `AcmPluginService.isEnabled()`。 |
| `AcmWorkbenchPage` / `AcmDiffPage` | 分别展示共享提示、文件操作和运行状态；不直接访问 Node/Electron。 |
| `AcmPluginNotice` | 读取/写入版本化 dismiss marker；进入 ACM 设置时清除 marker。 |

建议接口：

- `acm:startDiff`：请求 `{reference, candidate, stdin}`，返回 `{taskId}`。
- `acm:stopDiff`：停止当前对拍，返回是否存在活动任务。
- `acm:diffEvent`：事件 `{taskId, side, stage, status, result?, cleanupWarning?}`；stdout/stderr 不直接广播。
- `acm:diffDismissNotice` / `acm:diffNoticeState`：持久化提示 marker，值包含 `productVersion`、`dismissed` 和 `reason`。

结果状态集合：

`reference-failed`、`candidate-compile-failed`、`candidate-runtime-failed`、`candidate-timeout`、`candidate-output-limit`、`match`、`mismatch`、`cancelled`、`unsupported`。

## 技术方案比较

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 方案 A：新增 `AcmDifferService`，内部复用 Runner helper/Compiler，双任务事件由新契约表达 | 不改变单文件 Runner 的状态机；标准程序门禁和双方结果可明确建模；可独立测试和停止 | 增加一层编排与少量重复的临时目录/流收集逻辑 | **采用**，与当前单文件 Runner 边界最相容 |
| 方案 B：把 `AcmRunnerService` 扩展成任意 N 个 side 的通用流水线 | 复用更多执行代码，未来多文件/批量测试可扩展 | 破坏现有 Runner 事件语义和 UI；并发/串行、标准程序门禁、清理结果会使旧契约复杂化 | 暂不采用，待真实批量需求确认后再评估 |

比较器方案：

- token 数组一次性驻留内存：实现简单、首差异定位稳定；输出上限 4 MiB 使最坏内存可控，采用该方案。
- 流式 token 比较：更省内存，但需要跨 chunk 保存 token 边界和上下文，且不必要地增加错误面，暂不采用。

## 数据与迁移影响

- 不新增 SQLite 表，不改变备份格式；对拍源码、stdin、结果和 dismiss marker 不写入数据库备份。
- 提示 marker 属于便携设置，需将当前 ACM 设置从 `{enabled}` 扩展为 `{enabled, noticeDismissedAtVersion?}`，并保持 v1→v2 默认值兼容；版本变化由主进程当前 `RELEASE_CONFIG.productVersion` 比较。
- 用户主动打开 ACM 设置时清除 marker；插件禁用时页面读取状态并强制显示提示，不改变插件实际 enabled 值。

## 风险与缓解

1. 标准程序和待测程序输出可能达到上限；主进程按现有 4 MiB 限制截断并终止对应任务，IPC 只发送摘要，避免 Renderer 内存膨胀。
2. 一个程序结束后可执行文件被 Windows 锁定；每侧独立清理、有限重试，清理警告与比较结果分离，并在下次 Runner 初始化继续清理。
3. 双侧任务停止或超时发生竞态；每个 side 使用独立 task id/phase，活动任务只允许一个，停止会终止当前子树并等待关闭事件后再进入下一 side。
4. 持久化关闭提示可能掩盖插件状态；marker 仅控制提示可见性，disabled/unsupported/error 状态始终强制显示，并在设置入口清除 marker。
5. 两份代码使用不同临时目录但共享同一编译器；编译路径和环境通过现有 helper 的受控 PATH 构造，避免用户 PATH 或远程输入进入命令行。

## 测试策略

- 比较器单测：空输出、连续空白/CRLF、首 token 差异、尾部缺失、多余 token、前后文边界和输出上限。
- 服务单测：标准编译失败/运行失败、待测编译失败/运行异常/超时/输出限制、正常 AC/WA、停止竞态、清理失败重试和插件门禁。
- IPC 契约测试：请求大小、空源码、非法状态和 disabled/unsupported 拒绝；事件不包含完整 stdout/stderr。
- Renderer 测试：双编辑器空初始值、打开/保存/另存为、stdin 丢弃、差异片段展示、提示关闭共享、版本变化/插件禁用重新显示、监听器 cleanup。
- Packaged E2E：独立 `/acm-diff` 路由真实编译/运行 AC 与 WA、标准程序失败、待测程序失败、停止/超时、差异片段、控件恢复、AppX 入口和 ACM disabled gate。

## 未解决但不阻断第一版的问题

- 不做批量输入文件、对拍历史、随机生成器、多文件工程、并行运行或调试器。
- 完整 Release 性能、Store 安装和多 Windows 宿主矩阵仍按主计划单独验收。
