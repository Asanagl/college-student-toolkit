# v0.4.0 ACM 工具集开发计划

更新日期：`2026-09-02`

## 目标与边界

v0.4.0 在保留现有日程、课程表、考试、实验、成绩/GPA 和教务导入的基础上，增加面向校内 ACM 成员的本地优先 C++ 临时 IDE。产品仍使用 Electron、React、TypeScript 和 SQLite，不重写现有数据层。

已确认的范围：

- Windows 11 x64，最低 `10.0.22621.0`；非 Windows 保留入口但显示不支持。
- 内置受信插件 `acm-code-workbench`，不支持第三方插件、在线市场或运行时下载插件。
- 主窗口内嵌 Workbench；单文件 `.cpp`，不做多文件工程和源码旁本地头文件索引。
- CodeMirror 6 编辑器；支持模板、打开/保存/另存为、只读文件、外部修改检测、多标签和终端输出。
- 对拍面板的标准程序源码沿用 2 MiB 输入边界；待测程序源码按需求不设固定的产品输入长度上限，`diff-candidate` 文件打开/保存和直接粘贴执行均适用。编译/运行超时、stdin、stdout/stderr 和 128 MiB 临时目录物理配额仍然生效，staging 超限返回 `ACM_RUNNER_OUTPUT_LIMIT`；这不是重新引入 2 MiB 候选源码上限。
- 编译器优先使用内置 x64 MinGW；也允许用户选择本机 `g++.exe`。不修改 PATH、注册表或系统设置。
- 主进程负责编译/运行编排和资源限制；AppX packaged 版本使用受控 Windows
  native helper 和 Job Object 的 kill-on-close 清理进程树，开发环境或旧包缺少
  helper 时保留 `taskkill /PID /T /F` fallback。
- 编译失败、超时、输出超限和手动停止都通过稳定错误码和事件返回；没有编译器时仍可编辑和保存。
- ACM Runner 仅面向用户本人信任的本地源码；运行进程继承当前用户权限，Job Object/native helper 只负责进程树生命周期，不构成操作系统沙箱。不可信代码运行能力不属于 v0.4.0 交付范围。

## 架构与接口

```text
Workbench Renderer
  -> preload 最小白名单 (window.api.acm)
  -> main IPC handlers + zod 校验
  -> AcmPluginService / AcmFileService / AcmCompilerService / AcmRunnerService
  -> 临时目录、g++.exe、Windows 进程终止 helper
```

ACM 数据不新增 SQLite 表。便携设置从 v1 迁移到 v2，增加 `acm.enabled` 与版本化的 `acm.noticeDismissedVersion`；机器专用的编译器选择写入 `userData/acm-toolchain.json`，不进入备份。对拍源码、stdin 和结果仅存在页面会话中，不进入 SQLite 或备份。备份格式从 v2 递增为 v3，仍可导入 v1/v2。

主要 IPC 域为：插件状态、文档创建/打开/保存/释放/外部修改、编译器选择/探测、runner 启停和事件订阅、对拍启停/结果事件和提示 marker。Renderer 不能访问 Node、文件系统或 `ipcRenderer`。

## 风险与缓解

1. MinGW 闭包可能遗漏 GCC 内部程序、头文件或运行时 DLL，导致探针通过前的编译失败。通过 staging 清单、x64 PE 检查、`-dumpmachine` 和 Hello World 探针阻断打包。
2. Windows 进程树可能残留，影响退出和临时目录清理。AppX packaged helper 使用
   `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，并由直接负面测试验证 wrapper 结束后目标及后代退出；
   开发环境或旧包使用 `taskkill /PID /T /F` fallback，父进程已处于外部 Job Object 时的嵌套行为和完整 packaged 停止/超时矩阵仍需实机验证。
3. 外部编辑器覆盖源码会造成用户改动丢失。保存前比较大小、mtime 和 SHA-256；覆盖和另存为都需要明确确认；异步替换前再次校验目标，普通保存发现目标被删除时返回 `ACM_FILE_CHANGED`。
4. 异步文件操作可能在重复点击或退出时放大资源占用。文件服务用 `openGate` 限制最多 64 个打开/外部检查在途操作并复用同一文档的检查、用 `writeGate` 串行化保存并限制在途保存数量为 4、另存为对话框最多排队 4 个、拒绝同一文档重复保存，并在 `dispose()` 中等待已准入的打开/保存/对话框操作；候选源码仍不设固定长度上限，完整字符串 IPC 和磁盘预算风险保留。
5. 远程教务页面和 ACM 文件都跨越不可信输入边界。继续使用隔离 WebContentsView；ACM IPC 统一 zod 校验，路径拒绝设备路径、UNC、符号链接和非 `.cpp` 文件。
6. Store MSIX 可能把工具链误当作已验收的正式发布物。`verify:appx`、本地 smoke、Store 状态和实机验收分别记录，未签名/未上架包不称为 Stable。

## 阶段门禁

### 本轮审查结论

- 代码审查：`PASS`（2026-09-01 增量复核）。当前实现没有已知严重正确性、安全、数据损坏或结果判定问题；停止/禁用可绕过编译器探测的竞态已补充服务级回归测试，候选源码文件读取改为异步分块，保存改为异步临时替换；本轮又补充了对拍处置期间关闭新任务准入、终止失败后的阶段收束、清理重试生命周期登记和旧临时目录内部 reparse point 防护。审查记录了终止确认失败时的子进程残留跟踪、自动终止失败降级等非阻断警告，详见下方安全残余风险。
- 文件服务增量门禁已关闭：普通打开的 64 MiB 总量检查由 `openGate` 串行化；保存队列限制为 4 个在途操作并拒绝同文档重复请求；另存为覆盖确认在写入临界区内复核；外部检查按文档、路径和完整指纹去重；`dispose()` 等待已准入操作；释放文档不会被异步保存重新登记；普通保存的外部删除/替换会返回 `ACM_FILE_CHANGED`。打开对话框和另存为对话框的 64/4 admission 上限已有直接负面单测。
- 仍保留不阻断的文件系统与生命周期边界：路径检查与打开/替换不是 Windows 句柄级 no-follow 原子操作，外部进程仍可能在最后一次校验后制造 TOCTOU；打开/外部检查和另存为 admission 仍以固定数量而非字节背压为界；原生文件对话框若永久不返回仍会拖延退出，但页面卸载或服务释放后的打开/另存为请求会丢弃迟到结果，并取消大文件读取或覆盖写入登记；替换成功后的 `.bak` 清理失败不会回滚已成功写入的文件，而是返回成功结果附带 warning，并进行最多 3 次后台重试，进程崩溃后遗留的 pid-uuid `.bak` 会在文件服务启动扫描中回收，无关 `.bak` 不会删除；对拍和 Runner 现在对手动停止、自动超时、输出超限及流错误统一执行有限终止尝试，终止未确认时返回 `terminationError/cleanupBlocked`、保留活动任务和临时目录，并等待晚到的 `exit/close` 后再清理；终止 helper 或底层文件系统调用若永久挂起仍可能拖延退出，清理重试现有全局 pending 上限，超出后保留 owner marker 并转交下次启动；应用退出时若子进程仍未确认会明确记录，但仍可能残留外部进程；候选源码仍以完整字符串跨 Renderer/IPC 传递，且 Runner 只适用于用户本人信任的源码，不构成操作系统沙箱。
- 安全审计：`PARTIAL`。本轮没有阻断级高危漏洞；对拍/Runner 的终止失败状态机已统一为有限尝试、可观测 warning、退出确认前保留活动任务，自动超时/输出超限不再静默吞掉终止错误。仍保留 Windows 句柄级 no-follow/原子替换、候选源码 IPC 峰值、底层调用永久挂起、应用退出后未确认子进程可能残留和 Runner 非沙箱等 P2/P3 残余风险；这些风险属于当前“仅运行用户本人信任源码”的明确边界。未来若需支持不可信或超大源码，必须先设计分块 IPC/背压、磁盘预算和 Windows 受限执行环境。
- 因上述安全残余风险及 Store/实机/真实教务验收尚未完成，当前版本保持 `RC/PARTIAL`，不能称为 Microsoft Store `Stable`。
