# v0.4.0 ACM 工具集开发计划

更新日期：`2026-08-29`

## 目标与边界

v0.4.0 在保留现有日程、课程表、考试、实验、成绩/GPA 和教务导入的基础上，增加面向校内 ACM 成员的本地优先 C++ 临时 IDE。产品仍使用 Electron、React、TypeScript 和 SQLite，不重写现有数据层。

已确认的范围：

- Windows 11 x64，最低 `10.0.22621.0`；非 Windows 保留入口但显示不支持。
- 内置受信插件 `acm-code-workbench`，不支持第三方插件、在线市场或运行时下载插件。
- 主窗口内嵌 Workbench；单文件 `.cpp`，不做多文件工程和源码旁本地头文件索引。
- CodeMirror 6 编辑器；支持模板、打开/保存/另存为、只读文件、外部修改检测、多标签和终端输出。
- 编译器优先使用内置 x64 MinGW；也允许用户选择本机 `g++.exe`。不修改 PATH、注册表或系统设置。
- 主进程负责编译/运行编排和资源限制；AppX packaged 版本使用受控 Windows
  native helper 和 Job Object 的 kill-on-close 清理进程树，开发环境或旧包缺少
  helper 时保留 `taskkill /PID /T /F` fallback。
- 编译失败、超时、输出超限和手动停止都通过稳定错误码和事件返回；没有编译器时仍可编辑和保存。

## 架构与接口

```text
Workbench Renderer
  -> preload 最小白名单 (window.api.acm)
  -> main IPC handlers + zod 校验
  -> AcmPluginService / AcmFileService / AcmCompilerService / AcmRunnerService
  -> 临时目录、g++.exe、Windows 进程终止 helper
```

ACM 数据不新增 SQLite 表。便携设置从 v1 迁移到 v2，增加 `acm.enabled`；机器专用的编译器选择写入 `userData/acm-toolchain.json`，不进入备份。备份格式从 v2 递增为 v3，仍可导入 v1/v2。

主要 IPC 域为：插件状态、文档创建/打开/保存/释放/外部修改、编译器选择/探测、runner 启停和事件订阅。Renderer 不能访问 Node、文件系统或 `ipcRenderer`。

## 方案比较

| 领域 | 采用方案 | 备选方案 | 选择理由 |
| --- | --- | --- | --- |
| 编辑器 | CodeMirror 6 | Monaco | 包体和内存更小，足够覆盖单文件 C++ 临时练习；不承诺 IntelliSense。 |
| 编译执行 | 主进程 + 受控 Windows native helper（Job Object；开发/旧包 `taskkill` fallback） | Renderer 直接 spawn 或仅使用 `execFile` | 主进程可统一超时、输出、临时目录和进程树清理；helper 只负责进程归属，不接触 IPC 或文件 API。 |
| 工具链 | staging 后内置最小 MinGW 闭包，另支持用户 `g++.exe` | 依赖用户自行安装或在线下载 | 离线可用且不引入未知下载源；用户选择仍能覆盖缺少内置工具链的机器。 |

## 风险与缓解

1. MinGW 闭包可能遗漏 GCC 内部程序、头文件或运行时 DLL，导致探针通过前的编译失败。通过 staging 清单、x64 PE 检查、`-dumpmachine` 和 Hello World 探针阻断打包。
2. Windows 进程树可能残留，影响退出和临时目录清理。AppX packaged helper 使用
   `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`，并由直接负面测试验证 wrapper 结束后目标及后代退出；
   开发环境或旧包使用 `taskkill /PID /T /F` fallback，父进程已处于外部 Job Object 时的嵌套行为和完整 packaged 停止/超时矩阵仍需实机验证。
3. 外部编辑器覆盖源码会造成用户改动丢失。保存前比较大小、mtime 和 SHA-256；覆盖和另存为都需要明确确认。
4. 远程教务页面和 ACM 文件都跨越不可信输入边界。继续使用隔离 WebContentsView；ACM IPC 统一 zod 校验，路径拒绝设备路径、UNC、符号链接和非 `.cpp` 文件。
5. Store MSIX 可能把工具链误当作已验收的正式发布物。`verify:appx`、本地 smoke、Store 状态和实机验收分别记录，未签名/未上架包不称为 Stable。

```powershell
npm run typecheck
npm run lint
npm run format:check
npm run test:unit
npm run test:coverage
npm run build:electron
npm run stage:toolchain
npm run build:runner-helper
npm run package:appx
npm run verify:appx
npm run test:smoke:package
npm run test:smoke:appx
npm run test:runner-helper
```

`stage:toolchain` 只接受显式 `ACM_MINGW_SOURCE`，不读取密码、Cookie、令牌或私钥，也不会修改 PATH。所有 Store、安装、更新、卸载/重装、v0.2 迁移、真实教务导入和 OCR 实机项目，除非有独立证据，均保持 `TODO` 或 `BLOCKED`。
