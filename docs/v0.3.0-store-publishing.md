## 1. 两种产物不是同一件事

### 本地 Store-only 测试包

运行 `npm run package:appx` 可生成本地 x64 AppX/MSIX。打包脚本会在 electron-builder 生成包后，用 Windows SDK `makeappx.exe` 重建包清单和 block map；这是因为当前 electron-builder 版本的默认 `MinVersion=10.0.14316.0` 已低于 Microsoft Store 当前接受下限。仓库默认使用：

- Identity Name：`college-student-toolkit-local`；
- Application ID：`CollegeStudentToolkit`；
- Publisher：`CN=ms`；
- 输出目录：`release-v0.3.0-msix-local`。

Store 接受所需的最低系统版本固定为 `10.0.17763.0`（Windows 10 1809 及更高版本）；`MaxVersionTested` 默认写为 `10.0.26100.0`。`npm run verify:appx` 会拒绝低于该最低版本的包，避免把 Partner Center 已知会拒绝的旧清单再次上传。

这个包只用于检查 ZIP/manifest、ASAR、x64 原生 SQLite binding、图标资源和隔离启动。它不是 Partner Center 身份，也不是可以直接提交或交付给普通用户的 Store 包。

### 正式 Store 包

正式包必须使用 Partner Center 分配的准确身份构建。`CN=ms`、猜测的应用 ID 或仓库自定义的 Publisher 都不能用于正式提交。Store 的包签名、发布者信任、分发和更新由 Microsoft Store/Partner Center 管理；本地包验证不等同于审核通过或已公开发布。

## 2. 本地验证

在仓库根目录执行：

```powershell
npm ci
npm run typecheck
npm run build:electron
npm run package:appx
npm run verify:appx
npm run test:smoke:appx
```

`verify:appx` 会检查：

- `.appx/.msix` 存在且可读取；
- `AppxManifest.xml`、`AppxBlockMap.xml` 和 `[Content_Types].xml` 存在；
  - 本地基线 manifest 为 `0.3.0.0`；当前候选可通过 `APPX_EXPECTED_VERSION=0.3.11.0` 显式核对 Identity Version，且均为 x64、正确的显示名和 executable；
- ASAR 中存在 renderer、main 和 preload；
- 包内 `better_sqlite3.node` 是 x64 PE；
- Store 包不包含 `app-update.yml`。

`test:smoke:appx` 使用自动生成的临时 `userData` 启动 unpacked AppX 产物，检查 schema 2、七张业务表和默认公式 `SUM(credit * gradePoint) / SUM(credit)`，完成后删除该临时 profile。它不会读取或修改用户现有数据。

源码单测会把仓库根 `better-sqlite3` 重建为 Node ABI；为了避免 Electron ABI 误配，当前 smoke 查询脚本直接加载被测 unpacked 包 `resources/app.asar` 中的 JavaScript 与对应的 `app.asar.unpacked` 原生 binding。验证正式候选包时必须显式指定输出目录，不要在未确认的情况下重新运行 `npm run package:store`。

## 3. 正式 Store 构建

正式构建只接收以下不敏感的 package identity 字段：

```powershell
$env:APPX_IDENTITY_NAME = "<Partner Center Name>"
$env:APPX_APPLICATION_ID = "<Partner Center Application ID>"
$env:APPX_PUBLISHER = "<Partner Center Publisher>"
$env:APPX_PUBLISHER_DISPLAY_NAME = "Asanagi"
$env:APPX_PACKAGE_VERSION = "0.3.11"
$env:APPX_OUTPUT_DIR = "release-v0.3.0-msix-store-v19"

npm run package:store
$env:APPX_EXPECTED_VERSION = "0.3.11.0"
$env:APPX_EXPECTED_PUBLISHER_DISPLAY_NAME = "Asanagi"
npm run verify:appx
npm run test:smoke:appx
```

构建脚本会在缺少四个身份字段时失败，也会拒绝 `APPX_PUBLISHER=CN=ms`。Store 重传必须使用三段 `APPX_PACKAGE_VERSION`（当前候选为 `0.3.11`），清单生成 `0.3.11.0`；旧的 `APPX_SET_BUILD_NUMBER` 与 `APPX_BUILD_NUMBER` 会被拒绝。产品运行时版本仍是 `0.3.0`。构建命令不接收或保存密码、Cookie、私钥或访问令牌；如果某个外部流程要求这些凭据，应在 Partner Center 或受保护发布环境中完成，不要把它们交给仓库脚本。

## 5. 用户本人完成的最小实机验收

Store 包当前已公开；若日后需要完成 Stable 放行，需要在 Windows 11 x64 实机完成以下操作；验收记录只保留脱敏结果，不上传账号、密码、Cookie、完整 DOM、截图或成绩明细：

- 从 Store 页面安装并首次启动；
- 确认设置页显示 Microsoft Store 更新渠道；
- 用一个空 profile 创建和重启应用，确认数据仍在；
- 从 v0.2 profile 覆盖升级，确认七张业务表、公式、设置和背景按预期迁移；
- 从 Store 执行一次更新，确认应用可重新启动且 `electron-updater` 没有介入；
- 卸载应用后确认约定的数据保留行为，再重装并读取数据；
- 用户本人在导入窗口登录真实教务系统，分别完成课程、考试、实验各一次导入，并在应用内确认冲突结果；
- 在 OCR 未安装、下载取消、断网和组件损坏时确认 DOM/手动流程仍可用。

真实教务系统登录必须由用户本人完成。不要把教务账号、密码、Cookie 或可复用会话交给开发者或自动化脚本。
