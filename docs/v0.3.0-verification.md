### 原生模块 ABI 约束

Node 单测和 Electron 打包使用不同的 Node ABI。`npm run test:unit` 与 `npm run test:coverage` 现在都有前置 `npm rebuild better-sqlite3`，因此会自动重建当前 Node ABI；`electron-builder install-app-deps` 和 `package:appx` 会再重建 Electron ABI。验证顺序必须保持：

1. 先执行源码门禁和单测/覆盖率；
2. 再执行 `electron-builder install-app-deps --arch=x64` 或 `npm run package:appx`；
3. 最后用 Electron 启动 packaged/AppX smoke。

本轮已经分别验证：Node ABI `137` 可加载 SQLite，打包应用和正式 MSIX 内置的 Electron ABI `123` 原生 binding 可加载 SQLite；`test:smoke:appx` 的查询脚本已改为加载被测包内 `app.asar` 的 `better-sqlite3`，不再错误复用单测阶段的 Node ABI binding。

## 6. 安全与数据边界证据

- GPA 公式不再使用 `expr-eval`；共享解析器限制 token 数量、公式长度、变量名和运算符，并拒绝未声明标识符。
- 备份导入拒绝 Zip Slip、绝对路径、盘符、UNC、反斜杠绕过、重复条目、加密 ZIP、符号链接、未知文件和大小/哈希不匹配。
- 导入浏览器默认只允许 HTTPS，HTTP 每次需要一次性确认；拒绝 `file:`, `javascript:`, `data:`, 自定义协议、本地路径和带凭据 URL。
- 远程页面没有主应用 preload，使用 sandbox、context isolation、nodeIntegration 关闭和 webSecurity 开启；权限和下载均拒绝。
- OCR 只访问 manifest 中固定 HTTPS URL，下载到 `.partial`，压缩和解压内容各校验一次，成功后原子替换并保留旧模型。
- 备份中的个人学习数据未加密；密码、Cookie、登录会话和缓存不进入备份，也不应写入日志。
- Store 渠道解析为 `microsoft-store` 时不初始化 `electron-updater`，手动更新返回 `UPDATE_MANAGED_BY_STORE`。
- `npm run package:store` 在缺少 `APPX_IDENTITY_NAME`、`APPX_APPLICATION_ID`、`APPX_PUBLISHER` 时按预期主动失败，未用本地 `CN=ms` 身份冒充正式包。
