# v0.3.0 v19 聚焦代码审查记录

审查范围：本轮修复涉及的提醒调度、备份导出/导入恢复、OCR worker/下载重定向、三类导入确认、Store 更新边界与 MSIX 校验器。
结论：高风险路径已按源码修复并随 v19 编译封装；受影响单元测试通过，但这不是替代完整回归测试的“审查通过”证明。

| 风险 | 修复状态 |
| --- | --- |
| 导出目标覆盖数据库、设置或背景 | 已拒绝受保护路径，并通过临时归档后替换最终文件 |
| 导入回滚失败后删除恢复证据 | 已保留 `recovery-required` journal、staging 和恢复点 |
| OCR 缺失组件失败后同进程无法重试 | 已清理失败初始化 Promise，并在安装/移除时失效 worker |
| 部分 OCR/DOM 结果被填成虚构的日期、时间或节次 | 已拒绝不完整关键字段，要求用户手动补全 |
| 课程导入连续确认导致重复写入 | 已加入页面级同步锁和确认按钮禁用 |
| Store 退出时访问 GitHub updater | 已只在实际初始化 updater 后清理 listener |
| AppX 校验对错误 executable/native binding 假阳性 | 已校验真实可执行文件、精确 native 路径和更新元数据 |
| 提醒并发重算、休眠漏扫和发送失败重试 | 已加入串行重算、持久化 `lastScan`、扫描窗口和失败 retry 状态 |
| OCR 下载重定向到任意站点 | 已校验固定 GitHub 资产和真实 `release-assets.githubusercontent.com` host/path |
| 性能报告把 OCR skipped 误写成完成 | 正式 `PERF_ENFORCE=true` 要求 required metric、样本、p95 和真实 OCR 证据 |

未完成的完整审查范围包括：所有模块的单元/E2E 回归、覆盖率、正式性能、干净 checkout 实际重建、真实 OCR 识别、Windows 实机迁移和 Store 审核。
