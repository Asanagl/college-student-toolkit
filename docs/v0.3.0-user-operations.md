资料齐全后，开发侧可以继续代为填写草稿并逐页复核；“提交进行认证”、发布计划和真实 Windows/教务验收仍需要发布者本人决定或执行。

从 Partner Center 的产品包身份页面复制以下字段。请复制原值，不要手动猜测、改大小写或使用仓库中 `CN=ms` 的值：

| 字段                                  | 用途                    | 是否可以发送给开发侧 |
| ------------------------------------- | ----------------------- | -------------------- |
| `Name` / `Identity Name`              | MSIX manifest 的包身份  | 可以                 |
| `Application ID`                      | manifest 的应用 ID      | 可以                 |
| `Publisher`                           | manifest 的发布者       | 可以                 |
| `Publisher Display Name`              | manifest 的发布者显示名 | 可以                 |
| `PublisherId`                         | 用于核对包族名          | 可以                 |
| `Package Family Name`                 | 用于核对安装身份        | 可以                 |
| `Product ID`                          | Store 产品定位          | 可以                 |
| 账号密码、验证码、Cookie、私钥、token | 登录/签名凭据           | 不要发送             |

建议按下面的格式发送纯文本字段；不要附带账号截图或浏览器 Cookie：

```text
APPX_IDENTITY_NAME=<Partner Center 的 Name>
APPX_APPLICATION_ID=<Partner Center 的 Application ID>
APPX_PUBLISHER=<Partner Center 的 Publisher>
APPX_PUBLISHER_DISPLAY_NAME=<发布者显示名>
APPX_PUBLISHER_ID=<Partner Center 的 PublisherId>
APPX_PACKAGE_FAMILY_NAME=<Partner Center 的 Package Family Name>
STORE_PRODUCT_ID=<Product ID>
STORE_URL=<如果已经有公开页面则填写，否则留空>
```

其中前三个字段是开发侧重新构建正式 Store 包的最低要求。`PublisherId`、Package Family Name、Product ID 和 URL 用于发布后对照，不应写进仓库的秘密配置文件。

2. 记录卸载前的脱敏数据统计。
3. 从 Windows 设置或开始菜单卸载 Store 应用。
4. 按项目约定检查 userData 是否保留；不要使用清理工具强行删除数据目录。
5. 从 Store 重新安装并启动。
6. 确认数据和设置是否按预期保留；如果没有保留，使用 v2 备份恢复并记录结果。

反馈中只提供“保留/未保留/通过备份恢复”等结果，不要发送数据目录完整路径、数据库文件或个人数据。

## 九、阶段 6：真实教务系统导入

这一步必须由你本人完成。开发侧不接收真实账号、密码、Cookie、完整 DOM、完整截图或成绩明细。

### 6.1 课程导入

1. 在应用的课程表页面打开“自动导入”。
2. 在隔离的导入窗口中输入教务系统地址并登录。
3. 打开课程表页面，点击“开始识别”。
4. 优先使用 DOM 解析；确认待导入条目数量。
5. 在冲突解决界面检查课程名称、教师、时间、周次和地点。
6. 确认后批量写入。

### 6.2 考试导入

1. 在考试页面打开自动导入。
2. 选择或打开考试安排页面。
3. 识别后核对课程、时间、地点和考试类型。
4. 处理重复或冲突记录后确认写入。

### 6.3 实验导入

1. 在实验页面打开自动导入。
2. 识别实验名称、时间、地点和相关课程。
3. 处理冲突后确认写入。

### 6.4 OCR 选择

- DOM 内容完整时，不需要安装 OCR。
- 页面只有图片或 DOM 不完整时，在“设置 → OCR 识别组件”中由你明确点击安装，然后重新执行识别。
- OCR 未安装、下载取消或网络不可用时，应仍能使用 DOM 或手动录入。
- OCR 安装成功后，断网重新识别一次，确认已安装组件可离线使用。
- 若下载失败或 hash 校验失败，保留错误提示，不要手动替换模型文件或下载来源不明的模型。

### 6.5 真实导入反馈格式

```text
真实教务导入（不含账号信息）
课程：通过，识别__条，确认写入__条
考试：通过，识别__条，确认写入__条
实验：通过，识别__条，确认写入__条
冲突处理：通过 / 有问题（只描述现象）
OCR：未使用 / 安装成功并离线识别通过 / 未安装成功
登录凭据是否离开本机：否
错误代码或现象：无 / <脱敏信息>
```

关闭导入窗口后，确认应用仍能正常工作。不要把真实教务页面地址中的账号参数、Cookie、截图或完整 HTML 发回。

## 十一、遇到问题时的停止规则

出现以下任一情况，先停止后续写入和发布，不要连续重试：

- Partner Center 报包身份不匹配；
- 安装后数据库迁移失败或记录数明显减少；
- Store 更新后应用无法启动；
- 卸载/重装后数据状态与预期不符；
- 真实导入出现静默丢课、错误时间或重复写入；
- OCR hash 校验失败、模型来源变化或离线识别异常；
- 需要提供密码、Cookie、私钥或 token 才能继续。

反馈错误代码、发生阶段、应用版本、Windows 版本和脱敏现象即可。保留本地备份和原始错误，不要发送个人数据文件。
